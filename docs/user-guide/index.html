Learning Experience Engine

Interaction Builder Guide

Build reusable learning interactions without recreating the same Storyline mechanics every time. Normal authoring happens through instructional-design fields; internal IDs and structured project data stay under Advanced.

Step 1

Choose by learner behavior

Browse or compare · Carousel

Use for examples, benefits, personas, product signals, steps, or grouped content learners should move through.

Explore a visual · Hotspot

Use for diagrams, workflows, maps, interfaces, equipment, or any image learners should inspect.

Practice with a question · Knowledge check

Use for a focused question with answer-level coaching feedback.

Watch or listen · Guided media

Use for demonstrations, narrated examples, walkthroughs, or a sequence of audio/video segments.

Rule of thumb: choose the interaction based on the learner action, not the widget name.
Step 2

Add source files & media

Add your source folder when possible. The builder reads the files locally and can fill compatible image/media fields while you author.

You addHow it helps
Reference content (TXT, MD, CSV, JSON)Keeps source notes close to the interaction while you build.
ImagesAvailable for carousels, visual exploration, and supporting media.
Video / audioAvailable to guided-media interactions.
CaptionsMatching caption files can be recognized for local preview.
DocumentsStay packaged with the editable project for reuse.
Privacy: selecting a file does not commit it to GitHub. Confidential source files can stay in your private local workspace.
Step 3

Set the interaction basics

Give the interaction a learner-facing title, describe what it is helping the learner understand, and write a clear action instruction. Internal IDs are generated underneath and are hidden during normal authoring.

Build

Add the learning content

Carousel

Add the items learners should browse or compare. Each item can have a title, explanation, image, and alt text.

Visual exploration

Add a background image, then define what each hotspot should reveal. Position values are currently entered as percentages; direct click-and-place positioning is a future usability upgrade.

Knowledge check

Write the question, answer choices, identify the correct response, and give useful coaching feedback.

Guided media

Add each audio/video segment in sequence with captions or transcript content where needed.

Advanced fields: use the Advanced fields button only when you need to inspect internal identifiers. Most authoring does not require them.
Step 4

Preview

Use the embedded preview while you author. Choose Preview as learner when you want to focus on the experience without the editing controls, and Restart preview when you want to test completion again.

Advanced

Advanced project data

The structured data underneath the form is what makes the interaction portable and reusable. You normally do not need to edit it. It remains available for debugging, integration, and future automated workflows.

Important

Privacy and confidential work

The authoring app is public, but files you explicitly select are read locally in your browser. Keep confidential source folders outside the public repository and only export or publish sanitized content intentionally.

Help

Troubleshooting

I do not see the latest interface

Refresh the browser; Safari may cache older GitHub Pages files.

A media field did not fill automatically

Open Source files & media, confirm the file is loaded, then choose it for the relevant field.

Why can I still see technical data?

Advanced project data is intentionally still available for portability and debugging, but it is not part of the normal authoring workflow.
