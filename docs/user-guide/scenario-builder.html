Scenario Builder Guide

Build branching practice as an instructional designer: define the practice goal, write what is happening, give the learner meaningful choices, coach the decision, and show where each path ends. The state-machine details stay underneath.

Step 1

Start with the practice goal

Use the setup section to answer the core ID questions: What is the learner practicing? What action should they take? Which decision should they see first?

Good scenario design starts before branching. If the practice goal is vague, adding more branches will not make the experience stronger.
Step 2

Add source files & media

Add reference content and images before building decision points. New cards can automatically use unused images when possible.

Privacy: files stay local to the browser session unless you intentionally download an editable project. Keep confidential source folders outside the public repository.
Step 3

Build decision points like a simulation worksheet

PromptWhat to write
Who is speaking?The customer, manager, partner, peer, system, or other role presenting the situation.
What's happening?The learner-facing moment or decision context.
What does the learner know?Relevant context, constraints, evidence, or information available before the choice.
ImageAn optional visual that helps establish context.

Every decision point remains visible in the same canvas so you can review the whole simulation without jumping between separate editing screens.

Learner judgment

Write choices and coaching feedback

Each learner response should represent a believable decision—not just a quiz distractor. For each response, choose What happens next? and write Coaching feedback that explains the decision quality or consequence.

Learner response

What would the learner realistically say or do?

What happens next?

Send the learner to another decision point or an outcome.

Coaching feedback

Explain why the decision helped, hurt, or changed the conversation.

Impact on score

Optional numeric reinforcement when a simple performance score is instructionally useful.

End states

Use outcomes to close the learning loop

An outcome should explain what happened because of the learner's decisions and what they should carry forward. You can create successful, partial-success, recovery, or “more discovery needed” endings without labeling them as simply right/wrong.

Optional

Scoring is progressive disclosure

Open Optional scoring only when points add instructional value. You can name the score, set the starting/range values, and decide whether the learner sees it. If the scenario works better as pure decision practice, turn scoring off and ignore the rest.

Step 4

Preview

Use Preview to test the path in the page and Preview as learner for a focused simulation view. Take different routes and check whether coaching feedback, score changes, and outcomes support the intended learning objective.

Scenario check: the builder will tell you when something must be fixed before preview, such as a missing destination or unreachable outcome.

Advanced

Internal IDs and project data

The engine still needs stable IDs and structured data to maintain branches, rename destinations safely, and export portable projects. Those fields are hidden during normal authoring. Use Advanced fields only when you need to inspect or troubleshoot them.
