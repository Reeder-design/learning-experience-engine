User Guide

Scenario Builder

Scenario Builder creates engine-native branching learning interactions. Use it for customer conversations, judgment practice, choose-your-path simulations, decision coaching, and other experiences where learner choices change what happens next.

Workflow

Build a branching scenario in five steps

1

Scenario basics

Set the title, learner instruction, score behavior, and start node.

2

Upload assets

Load source context and visuals before authoring so image fields can use portable project paths.

3

Build decisions

Edit all decision nodes and outcomes in one canvas. Add choices and select their destinations from dropdowns.

4

Preview

Run alternate paths, review feedback and score changes, and confirm each outcome.

5

Export

Export engine-native JSON or a complete project ZIP.

Step 1

Scenario basics

The title, description, and learner instruction are learner-facing. The score settings control the single decision-quality score used in Scenario Builder v0.1.

Start node: every preview begins at the selected decision node. Only decision nodes can be used as the start.
Step 2

Project assets

Load a project folder or individual files before building the path. Images become options in node/outcome visual selectors. TXT, Markdown, CSV, and JSON source-context files are readable in the asset section but do not automatically become learner content.

scenario-project/
├── context/
│   └── source-content.txt
├── assets/
│   └── images/
│       ├── customer.jpg
│       └── outcome.jpg
└── component.json
Step 3

Decision nodes

A decision node is one moment where the learner must choose what to do next. Every decision card stays visible on the same authoring canvas.

Node ID

A stable internal reference. Keep it short and unique. If you rename it in the interface, existing choice targets are updated for you.

Speaker / role

Optional context such as Customer, Manager, Partner, or Team Lead.

Situation

The title and details explain what is happening before the learner makes a choice.

Visual

Optional image selected from the project asset library.

Branching

Choices, feedback, and targets

Each choice has four important values: learner-facing choice text, a destination, immediate coaching feedback, and an optional score change.

FieldPurpose
Choice textWhat the learner selects.
Send learner toAnother decision node or an outcome. Use the dropdown; do not type IDs manually.
Score changePositive, negative, or zero adjustment to decision quality.
Immediate feedbackCoaching shown before the learner continues down the branch.
Completion

Outcomes

An outcome is an endpoint. Reaching any outcome completes the engine component. Outcomes can include an explanation, visual, and learner takeaway/next step.

A scenario can have multiple outcomes. They do not need to be labeled “good” or “bad”; use outcome language that fits the instructional purpose.
Guardrails

Path check

Scenario Builder continuously checks the branch structure. Blocking issues include duplicate IDs, missing destinations, missing start nodes, nodes with no choices, and scenarios where no outcome can be reached.

Unreachable nodes or outcomes are shown as warnings. They do not make the rest of the path invalid, but they indicate content the learner cannot reach from the current start node.

Step 4

Preview

Preview from beginning runs the current scenario inline. Open focused preview opens the learner experience in a larger modal so you can test alternate paths without the authoring cards competing for attention.

The preview supports choice feedback, score changes, path history, outcomes, and replay.

Confidential work

Privacy

Scenario Builder runs as a static browser application. Files you explicitly select are read locally for preview and project packaging. Selecting them does not commit them to the public GitHub repository.

For confidential work, keep the source project in the private local workspace and use the public engine only for reusable mechanics and generic templates.
