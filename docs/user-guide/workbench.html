User Guide · v0.4

Edit the published learning experience.

The Workbench is for reconstructing, generating, transforming, previewing, and exporting published-style learning web experiences. It does not try to recreate the Rise or Storyline authoring interfaces. Branching scenarios are the first complete project type.

Workflow

Four stages, four project tools

1

Source

Describe the learning need and add reference files, published-web source material, and media.

2

Build & edit

Edit learner-facing content and interaction behavior. Internal IDs are maintained automatically and are not part of normal authoring.

3

Preview

Render and test the experience as a learner, including the current project theme.

4

Export

Download portable Engine JSON, or a private project ZIP with the editable project, brief, history, uploaded source files, and available small media previews.

Project tools are not workflow steps. Ask AI, Theme, History, and Project settings stay available across the project.
Starting points

Five ways into a project

Start from a template

Use a prebuilt scenario structure such as customer discovery, decision practice, or objection handling. Replace the learning content while keeping the mechanics.

Start simple

Begin with one decision point and one outcome when you do not need a template structure.

Open a saved project

Choose an existing Engine project JSON file or a Workbench project ZIP. A project ZIP restores the editable project plus the private source files and available small media previews that were bundled with it.

Import a Rise web export

In the password-protected local Workbench, choose a published Rise ZIP export. The Workbench reads it locally and creates an editable normalized course draft: lessons, exposed block text, and quiz questions. It does not edit a native .rise authoring file, and every imported block should be reviewed before reuse.

Import a Storyline web export

Choose a published Storyline ZIP export to create an editable normalized scene → slide → layer draft. The Workbench surfaces scene names, slide titles, layer labels, and exposed object text or alt text. It does not edit a native .story authoring file; triggers, variables, conditions, timelines, and custom JavaScript remain review items in this first pass.

Source files

What happens to uploaded files?

Files stay local to the current browser session until you explicitly run an AI action. Text-like reference files (TXT, Markdown, CSV, JSON) can be read in the workspace. Images become selectable in decision/outcome fields and can appear in the learner preview.

Explicit send only. Selecting a source file does not send it anywhere by itself. In password-protected local mode, Generate or Apply AI changes can send the selected reference material to the configured OpenAI API project for that request.
Project tools

AI, theme, history, and settings

Ask AI

Generate from source, sanitize, adapt an audience, create a similar version, or make a freeform project change. AI returns both the interaction and the Workbench Project Profile.

Theme

Theme is first-class presentation data: colors, typography, layout treatment, identity rules, motion, accessibility expectations, and target-specific notes for standalone web, Rise embed, Storyline Web Object, and LMS packaging.

History

Every successful AI action creates a version with its prompt, model, before/after project snapshots, and change summary. You can restore the version, restore the state before it, or restore the starting point and edit/rerun the instruction.

Project settings

Audience, purpose, objectives, duration, prerequisites, navigation, progress, feedback, scoring behavior, source origin, and experience structure live outside the interaction JSON's learner-facing fields.

Private local mode

Password protection and local secrets

Run npm run workbench from the repository. The server binds only to 127.0.0.1. On first launch, the browser asks you to create a Workbench password and optionally add the separate OpenAI API key.

  • the password is stored only as a salted PBKDF2-SHA256 hash
  • the API key and password hash live in Git-ignored .env.workbench
  • the login uses an HttpOnly, SameSite=Strict session cookie
  • modifying API requests require a CSRF token
  • sessions expire after about 8 hours
  • Private settings lets you rotate the API key, switch AI models, or change the password later
Public GitHub Pages is not the private manager. The public Workbench remains a safe demo/manual editor; private AI and confidential source workflows are intentionally local-only.
Published-web target

What the Workbench is—and is not

The goal is to edit and transform the published learning webpage/package, not to clone the proprietary Rise or Storyline authoring UI. A Rise-like project exposes course → lessons → blocks; a Storyline-like project exposes scenes → slides → layers. Both share source handling, Project Profile, themes, history, preview, and export systems.

Current boundary. Branching scenarios are complete end to end. Rise and Storyline published-web imports can become editable normalized drafts, and small available media previews can travel in a private project ZIP. Richer block/object editing, complete source-asset handling, production behavior editing, and exporters for Rise/Storyline/LMS remain future work.
